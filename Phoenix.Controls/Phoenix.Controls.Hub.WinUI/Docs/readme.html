Phoenix Controls

A professional-grade stream management suite for Twitch, YouTube & Kick streamers. Phoenix Controls replaces a stack of fragmented overlay tools, chatbot helpers, and one-off scripts with a single coordinated app that shares an IPC bus and a SQLite databank. You design your bot logic visually in Architect, design your OBS overlays visually in Visualist, and let Hub run everything live while you stream.

The three pillars

Three pillars in one app: Hub is the running process, and Architect and Visualist are design-time pillars hosted as tabs inside it. They share a local WebSocket bus and a SQLite databank.

The runtime

Hub

Phoenix.Controls.Hub.WinUI.exe

The only process that talks to Streamer.bot, Twitch and OBS — the "always-on while you stream" app. Live Event Feed, Chat Monitor, Script Monitor and System Log. Hosts the HUD overlay server (:18080) and the IPC bus (:18081).

The logic builder

Architect

A pillar tab inside Hub

Where you build bot behaviour. Drop nodes on a canvas, wire them Unreal-Blueprints style, and Architect compiles the graph into a .phx script Hub picks up automatically. Never talks to Twitch directly — bus only, for live debug.

The compositor

Visualist

A pillar tab inside Hub

Where you build OBS overlays. Each .phxlayer is one OBS browser source; place widgets and author per-trigger behaviour as a node graph. Triggers fire from Architect via Visual.Trigger and run in OBS.

Your first overlay

A minimal "type a chat command, see the bot reply" loop — the whole thing in six moves.

  1. In Architect, File → New and save hello.phxg into Hub's logic folder.
  2. Press Space (or right-click) and spawn Chat.Message, Logic.If and Chat.Send.
  3. Wire the flow through, set Logic.If so {user.command} equals hello, and set Chat.Send's message to Hello, {user.name}!.
  4. Save — Architect exports hello.phx and Hub hot-reloads it within ~250 ms (watch the Script Monitor).
  5. Type !hello in your chat — a green pulse flashes through the nodes and the bot replies.
  6. Make it visible: fire a Visual.Trigger into a Visualist layer and add a browser source at http://127.0.0.1:18080/layer/main.

Press F1 on any node — or open the Node Reference — for the full catalogue, the {token} vocabulary and every keyboard chord.

Install (for streamers)

  1. Download Phoenix Controls Setup <version>.exe from the GitHub Releases page (~3–5 MB; needs internet during install to fetch + SHA-verify the runtime payload).
  2. Run it. SmartScreen warns because the app isn't code-signed yet — More info → Run anyway (a signing cert is on the roadmap).
  3. Follow the wizard. Default is a per-user install under %LocalAppData%\Programs\Phoenix Controls\ — no admin prompt.
  4. If the .NET 8 Desktop Runtime is missing, the installer points you to Microsoft's download, then re-run.
  5. Launch from Start Menu → Phoenix Controls → Hub. Updates are handled in-app under Tools → Settings → Updates.

Settings cheat sheet

StreamerBotUrlWhere Hub finds Streamer.bot's WebSocket Server (default ws://127.0.0.1:8080/).
HUDServerPortPort the OBS browser-source overlay listens on (default 18080).
BotUsernameComma-separated bot accounts whose chat scripts ignore — prevents self-triggering.
ScriptTimeoutSecondsMax seconds a single script run may take before cancel (default 30, 0 = unlimited).
OpenAIApiKey / AnthropicKeyAPI keys consumed by the AI.Prompt / AI.Moderate nodes.

Troubleshooting, fastest first

  • Streamer.bot indicator red — Streamer.bot isn't running, its WebSocket Server is off, or the URL doesn't match Hub Settings.
  • OBS source blank — the URL must be http://127.0.0.1:18080/layer/<id> (note /layer/), the HUD dot must be green, and the source size must match the layer resolution.
  • Chat triggers nothing — either Streamer.bot isn't forwarding chat, or BotUsername is set to your own handle.
  • Anything else — open Hub's System Log and scroll back; every component logs there with a category prefix.
